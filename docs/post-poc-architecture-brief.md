# After the POC: proposed route to a playable native segment

**Research recommendation, 2026-10-18.** No architecture change or new acceptance result is adopted by this brief. This is a source and evidence assessment of public commit [`5ce82929025d8e2168b4c299b79fe87f31bb8cc7`](https://github.com/LucioFranco/orbiter-native/tree/5ce82929025d8e2168b4c299b79fe87f31bb8cc7), independent of any later `main` changes. The exact simulation inputs are OpenOrbiter `bd1d101f348da66e8c5b986633127c05e18d42c8` and NASSP v9 release 434 `e731c28c0ebc1a4fe3b63f99e2006a1a8a2b42a9` ([README.md:8–15](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/README.md#L8-L15)). No build, simulation, VM, or hosted run was performed for this brief. The reviewer checked 43 pinned source links and 1,015 source-snapshot hashes in private research evidence; that local evidence bundle is not part of this repository. Any performance target or proposed experiment below is a decision criterion, not an observed result.

## Executive recommendation

**Evolve the existing C++ native host and SDK boundary in small, removable pieces (option 1), using narrow seam replacements only where a differential test demonstrates a problem (option 3). Defer wholesale migration of host responsibilities into upstream Orbiter (option 2) until an actual upstream-update rehearsal and callback parity tests show which hooks can be shared.** Keep the original Orbiter physics, NASSP vessel systems, yaAGC/yaAGS, scenarios and ROMs. The fixed-step host, module ABI, data preflight and C++/Rust graphics boundary already support real bounded segments. The known strict AGC restart failure resides in NASSP/yaAGC snapshot ownership; the 60-second byte-repeatability failure is tied to inherited RNG/rigid-body scheduling. Neither points to replacing the physics core. This is a maintenance choice, not a claim that current native behavior is fully equivalent to stock Windows.

The largest *measurable* architecture risk is lifecycle drift: native `Orbiter::Launch` and `StepSimulation` substitute for upstream `Orbiter.cpp`, including initialization, input, callbacks and cleanup. For example, upstream invokes each plugin's `opcLoadState` before simulation start, while native `Launch` proceeds from vessel/MFD state loading to `clbkSimulationStart`; the shared save routine still emits `opcSaveState` sections ([upstream host:803–834](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Src/Orbiter/Orbiter.cpp#L803-L834), [native host:118–147](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Src/Orbiter/NativeHost.cpp#L118-L147), [save:211–238](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Src/Orbiter/FileAPI.cpp#L211-L238)). NASSP's RTCC MFD defines both callbacks but is not among the default native mission modules ([ARoapiModule.cpp:128–133](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Addons/NASSP/Orbitersdk/samples/ProjectApollo/src_rtccmfd/ARoapiModule.cpp#L128-L133), [NativeNassp.cmake:48–70](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/cmake/NativeNassp.cmake#L48-L70)). This is a **verified missing compatibility step and a testable risk for a future module**, not proof of the present strict AGC failure or of a current default-demo regression.

## The two strict failures have different owners

**Faithful AGC restart is a NASSP/yaAGC snapshot problem.** The full-suite record is 103/104 (one unfiltered serial macOS invocation); `native_pdi_pilot` deliberately fails because `CYCLECOUNTER` saves 124205511 and reloads 0 ([validation manifest:1–16](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/upstream/validation-v9-final-current-macos-2026-10-12.json#L1-L16), [NativePDIPilot.py:245–249](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Tests/NativePDIPilot.py#L245-L249)). `ApolloGuidance::SaveState` writes that counter; `LoadState` explicitly leaves its read disabled until CDU FIFOs can be restored ([apolloguidance.cpp:443–452](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Addons/NASSP/Orbitersdk/samples/ProjectApollo/src_sys/apolloguidance.cpp#L443-L452), [535–540](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Addons/NASSP/Orbitersdk/samples/ProjectApollo/src_sys/apolloguidance.cpp#L535-L540)). The FIFOs/checker are module-static in `agc_engine.c`, not per-`agc_t` ([1385–1388](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Addons/NASSP/Orbitersdk/samples/ProjectApollo/src_sys/yaAGC/agc_engine.c#L1385-L1388)); LM and CSM modules each have their own copy, while two AGCs of the same module share one. The [pending-state investigation](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/upstream/validation-agc-pending-state-macos-2026-10-10.json) also inventories wrapper `LastCycled`, gyro/coarse residuals and PCM interrupt phase. Its isolated helper proves a full private FIFO copy continues an exact 1,500-cycle trace and counter-only restoration differs; it **does not** prove a production serializer. Recommendation: preserve the strict red test, write a full ownership and atomic-boundary design first, and start implementation only as a separate approved workstream. Never “fix” this by loading the counter alone or relaxing observation bounds.

**Exact 60-second repeatability is shared upstream RNG/rigid-body behavior.** The separate no-driver check fails outside the 104 registered tests. NASSP mission timers reseed the process C RNG from wall time; Orbiter bodies initialize an update counter from `rand()`; `Rigidbody` flushes accumulated increments at counter 1000 ([missiontimer.cpp:42–48](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Addons/NASSP/Orbitersdk/samples/ProjectApollo/src_sys/missiontimer.cpp#L42-L48), [Body.cpp:34–40](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Src/Orbiter/Body.cpp#L34-L40), [Rigidbody.cpp:263–271](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Src/Orbiter/Rigidbody.cpp#L263-L271)). I independently checked those expressions and `Vecmat::irand` directly in the local pristine Git objects for both exact upstream commits. The [repeatability diagnosis:24–78](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/docs/native-v9-repeatability.md#L24-L78) documents seed-preserving traces and diagnostic fixed-seed controls: first observed differing final save at step 920 is tiny velocity/radar-rate residual, with no production seed change. Next investigate an explicit test-only seed/observer contract and measure stock Windows phase behavior; do not tune dynamics or silently make a diagnostic interposer a production dependency. The two failures must have separate owners and exit gates.

## Three directions, compared before choosing code

| Option | What would change | Expected maintenance gain | Cost and decision test |
| --- | --- | --- | --- |
| **1. Evolve host/SDK adapters** (recommended default) | Keep `NativeHost`, SDL, VFS, miniaudio and WgpuClient; fix observed host callback gaps and replace individual native branches with shared platform interfaces. Maintain source-list/preflight and per-group patch inventory. | Preserves original runtime, existing bounded gates, and quick adoption of NASSP v9 revisions. Small changes can be retired one group at a time. | Native/upstream host drift persists. Require lifecycle trace comparison and a next-pin rehearsal before calling it maintainable. |
| **2. Fuller upstream Orbiter core integration** | Move selected common lifecycle/SDK services into upstream core so stock and native invoke the same initialization, save/load and step path; keep platform/window/renderer implementations behind interfaces. | Could eliminate duplicated callback sequences and reduce future merge work if upstream accepts the seams. | High coordination and regression cost across stock Windows behavior and addon ABI. A one-callback prototype must actually reduce differential behavior and patch count; no direct core migration yet. |
| **3. Replace only a demonstrated seam** | Examples: add missing native plugin load-state dispatch, extract a common lifecycle helper, put path/module-name resolution behind one SDK service, or implement a reviewed per-AGC snapshot extension. | Can close a specific failure without broad engine or NASSP rewrites. | Each seam still needs parity, compatibility and removal path. A snapshot extension is substantially wider than one FIFO and stays separately gated. |

## Smallest discriminating investigations, in order

1. **Lifecycle/callback trace fixture, read-only first.** List upstream and native startup, pause, pre/post, plugin state, save, teardown events at source level, then design one throwaway plugin fixture that emits a named `opcSaveState` token and checks it after native reload. Compare original Windows host with identical scenario/module only when later execution is authorized. *Decision:* if a tiny native dispatch restores the token with no changed step boundary, use option 3 and propose the common callback contract upstream; if many callback order gaps appear, prototype one shared host routine for option 2. Keep `native_manual_step_alignment` time/counter boundaries, original mission checks and strict AGC result unchanged ([NativeManualStepAlignment.py:5–17](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/Tests/NativeManualStepAlignment.py#L5-L17)).
2. **State observability without a serializer rewrite.** Design a no-mutation, frame-boundary record of exact AGC cycle, three FIFO rings/checker, gyro/coarse residuals, `LastCycled` fractional phase, PCM phase, and full-precision body state for original uninterrupted and save/reload runs. Verify observer neutrality against existing untouched runs before interpreting any difference. *Decision:* identify the first field diverging; if it matches documented missing snapshot state, scope a per-instance extension and strict continuation test in a separate proposal. If the trace shows a host save/load callback issue first, fix that seam before touching AGC. Do not infer causality from the current two-count pointer residual: the pending-state ledger calls it unisolated.
3. **RNG/repeatability boundary experiment.** Repeat the existing end-only seed-preserving and diagnostic controls on the same exact pins, record body initialization counters and first flush, and add a stock Windows run with its compiler/runtime identity. Keep the untouched runner as the red reference. *Decision:* choose a documented deterministic test mode only if stock/native evidence establishes desired semantics and the mode leaves normal production input/physics unchanged. A fixed diagnostic seed is not an acceptance pass.
4. **Matched renderer/path probes only where visible behavior demands them.** One same-state/same-asset daylight/terrain capture pair can tell missing tile levels from shading. One case-collision and mixed-separator fixture can test VFS behavior on macOS/Linux. These do not require a new simulation architecture; promote each only if the playable segment needs it.

## Measurable adoption and clean-machine gates

**Upstream-update rehearsal.** First reconstruct the pinned NASSP v9 source from pristine `e731…` plus ordered groups 01–09, preserving the special group 08 two-stage regeneration, and compare every inventoried normalized file hash and all 14 source-list exports. Then in a disposable branch choose *one* newer upstream commit only after pinning its hash; record changed source lists, patch apply/three-way conflicts, manual resolution count and hours, files outside intended adapter groups, external data/version changes, and registered-test deltas. Repeat for an OpenOrbiter pin separately. Compare the exact original insertion, liftoff and uninterrupted PDI/P64 boundaries before expanding scope. Proposed go target: reconstruction is hash-exact; the next-pin port fits within two engineer-days, has zero unexplained conflicts or hidden source/data bindings, and introduces no unreviewed equation, ROM, scenario or acceptance-rule changes. The two-day target is a planning threshold to revise with the first measured rehearsal, not a claim about current effort. A clean new pin must generate its own suite counts and evidence, never inherit `103/104` by description. Use [`nassp_upstream.py`](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/tools/nassp_upstream.py) and the recorded [two-stage group 08 procedure](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/orbiter/docs/upstream-native-adoption.md#L114-L145) as starting tooling, with its historical pin replaced explicitly.

**Clean-machine validation.** On a newly provisioned Apple Silicon macOS machine, clone only the published commit, fetch the exact pristine NASSP data input and independently acquired planetary textures, record OS/compiler/SDK/CMake/Rust/Cargo/dependency revisions, run the full source/asset preflight, configure/build without another checkout's cache or private QA app, enumerate all registered tests, then run the CPU suite and a coordinated GPU/desktop/full suite. Use fresh runtime directories for original scenarios and record binary/input hashes, logs, output, complete pass/fail/skip counts and exit status. The current reproduction guide supplies the CLI and data checks ([docs/native-reproduction.md:8–53, 74–145](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/docs/native-reproduction.md#L8-L53)). Windows/Linux native compile probes and stock Windows comparison are additional evidence; macOS success alone does not grant cross-platform parity. Do not use a packaging preview as this validation; its rights/relocation gates are separate.

## Proposed v1 playable-segment contract

Choose **the original Apollo 11 lunar liftoff T−1 minute scene through separation and the first 30 simulated seconds of initial climb** as the first user-facing slice. This is an actionable proposal; the existing live record reaches 10.8167 seconds after manual START/release and verifies separation, full ascent thrust, plume and positive climb, not the proposed full 30 seconds ([validation-and-open-problems.md:40–47](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/docs/validation-and-open-problems.md#L40-L47)). The segment uses the pristine v9 scenario and matching data, one fixed 1/60-second simulation step, keyboard/laptop mappings, paused cockpit, visible DSKY/FDAI/MFD state, manual START and release, F5 pause/resume, and normal close with source inputs unchanged. State explicitly that the source scenario is pre-primed: fresh HE PRESS/ASC FIRE has not been proven. Saves from this slice may be archival/evidence only until faithful AGC reload passes; the UI and guide must not advertise playable restart. No orbit, landing, physical controller or full Apollo checklist claim.

Before calling it v1, require a fresh original-scene run from a clean machine that completes the whole bounded slice with actual user input/readbacks and a normal exit; an independent fixed-step regression of vessel count, stage separation, AGC/DSKY and thrust/climb boundaries; the exact input/asset hashes; and a desktop frame-time trace with a stated target agreed *before* tuning. A candidate product target is at least 95% of presented frames within 33 ms on the named test Mac, with simulation step count/time audited separately; this is not a current performance result. Add fresh HE actuation and physical-device gates only if those controls enter the advertised slice. Keep the strict resume test red and reported until its own capability is implemented, and keep the separate repeatability failure visible.

**Preserve from the POC:** fixed manual-step harness and time/cycle boundary tests, original mission staging/preflight and stock Windows comparison protocol, module ABI/VFS/SDL services, C++ Orbiter/NASSP numerical code, graphics-client/Rust ABI, and grouped source-removal manifests. **Candidate upstream contributions:** small portable SDK/VFS/module-loader behavior with conformance fixtures; common documented lifecycle/save-load callback order once measured; isolated NASSP compiler/path fixes; and the already separated loader/throttle/mass persistence group after exact native/stock zero-step and continuation review. Source-list overlays may remain downstream until an upstream native build policy accepts equivalent behavior. Do not offer the full port as an undifferentiated patch or present upstream adoption as already agreed.

**Stop/go before major refactoring:** proceed with option 1 plus proven option 3 seams while next-pin reconstruction and v1 slice stay green at their declared boundaries, source conflicts remain explicable and per-group removals are measurable. Consider option 2 only if the lifecycle fixture exposes multiple independent gaps that cannot be resolved with small shared interfaces, and a prototype demonstrably removes duplicated code/patch hunks without changing stock Windows callbacks or original mission results. Halt any core migration or language rewrite if it changes unexplained state/timing, requires loosening strict assertions, breaks next-pin adoption, or lacks a rollback path. A broad AGC snapshot implementation remains a separate design decision with atomic per-instance ownership and same-boundary continuation as its entry gate; its currently paused status is respected.

## Limits of this assessment

All code links above refer to `5ce8292`; local `main` may have advanced for CI after publication. The full 104-test evidence belongs to earlier tested source `0bd60e8`, and the published candidate's separate clean build/63-CPU-test report is documented at [validation-and-open-problems.md:8–17](https://github.com/LucioFranco/orbiter-native/blob/5ce82929025d8e2168b4c299b79fe87f31bb8cc7/docs/validation-and-open-problems.md#L8-L17). This brief did not rerun either. It has not measured fresh-machine build time, stock Windows lifecycle traces, next-upstream-pin merge cost, 30-second playable performance, or the full AGC pending-state trace. Those are experiments and gates above, not findings already established.
