# Native NASSP v9: licensing and publication audit

Audited 2026-10-12. Baseline: `49c0046ab581a78296edfa92ae5cf45c71be2b14`.
OpenOrbiter: `bd1d101f348da66e8c5b986633127c05e18d42c8`.
NASSP release434: `e731c28c0ebc1a4fe3b63f99e2006a1a8a2b42a9`.

This is an evidence-based release assessment, not a legal guarantee. It preserves existing grants, identifies unresolved rights, and proposes a conservative distribution boundary. No license was replaced; no checkout, index, visibility, hosted CI, simulator or remote was changed. Later documentation changes and the final pushed ref need a fresh review.

## Readiness verdict

| Proposed action | Assessment at this baseline |
| --- | --- |
| Publish the complete existing Git history as a public, uniformly open-source repository | **Not cleared.** A tracked font expressly restricts publication; proprietary/prebuilt files and third-party asset rights remain unresolved. |
| Publish an audited source/patch subset with original notices and explicit exclusions | Feasible, after the publication tree/history is selected and checked. An exclusion at the tip alone does not exclude an ancestor's blob. |
| Distribute a native OpenOrbiter/NASSP binary plus corresponding source | Feasible in principle under GPLv3-compatible terms, after resource/asset rights, notices, dependency source and packaging are completed. Current local build success is not artifact-compliance proof. |
| Release a ready-to-run bundle containing all installed NASSP/planetary/audio inputs | **Not cleared.** Asset provenance and redistribution scope must be documented per included set. |
| Redistribute the Windows VM or its proprietary setup prerequisites | Outside this release. Users acquire Windows, SDKs, runtimes and licensed audio prerequisites separately. |

## Publication blockers and findings

### 1. Architext is a concrete public-source and stock-Windows package blocker

`orbiter/Extern/imgui/architext.regular.ttf` is tracked and reachable from the initial imported history. Its accompanying `architext.regular - FFC License.txt:24-34` restricts modification and publication without the author's written permission. The Windows font installation in `orbiter/Extern/imgui/CMakeLists.txt:14-16` also copies it into the package. The upstream MIT root does not cancel this nested license. The [exact pinned text](https://raw.githubusercontent.com/orbitersim/orbiter/bd1d101f348da66e8c5b986633127c05e18d42c8/Extern/imgui/architext.regular%20-%20FFC%20License.txt) agrees with the [publisher's license](https://www.1001fonts.com/licenses/ffc.html).

Exclude/replace this font and update affected packaging references, or obtain a verifiable publication grant. A permission request has not been made. Merely deleting the file in a new commit leaves it in public history. The native build uses the separately licensed Roboto/JetBrains Mono fonts and does not select Architext; this permits a useful native release boundary without claiming the full tree is cleared.

### 2. Existing history includes non-source binaries and rights-sensitive material

Tracked examples include `orbiter/BinAssets/msvcp71.dll`, `msvcr71.dll`, Microsoft HTML Help import libraries, legacy NASSP `src_aux/{dinput8,dsound,dxguid}.lib`, `orbiter/Utils/plsplit/DxTex.exe`, D3D9 `InterfaceBuilder.exe`, prebuilt celestial-body DLLs and Qt-tool libpng/zlib libraries/PDB. There is no demonstrated redistribution grant for every such byte in the audit. Some may be distributable under separate SDK/runtime terms; that must be established rather than labeling all of them MIT/GPL. The root legacy NASSP tree also retains obsolete data and duplicates modern assets.

A public-source allowlist should omit unrelated SDK/installer/import-library/runtime binaries and publish build instructions referring to licensed prerequisites. If keeping any binary, record its origin, exact hash, applicable redistribution grant and notice. Inspect the original licenses for Office/PDF documents, third-party scientific papers, PSD/texture artwork and recorded sound. Public availability upstream and matching checksums establish provenance, not ownership or redistribution permission.

### 3. A GPLv2-only description is wrong for the combined preview

Most NASSP source headers and `Doc/Project Apollo License.txt:4-7` grant GPLv2 **or later**. `src_rtccmfd/{LDPP,LWP}.{cpp,h}:7-10` grant GPLv3 **or later**. These files are in the MCC/ApolloRTCCMFD source lists; for example `Project/MCC/CMakeLists.txt:47,51`. The core yaAGC files grant GPLv2-or-later, with their own Orbiter SDK linking exception (`src_sys/yaAGC/agc_engine.c:20-28`). A version-2 license text in the root does not turn all files into GPLv2-only code.

The native renderer also depends on Apache-2.0 components. The cached lockfile inventory finds five Apache-only packages: `codespan-reporting`, `gl_generator`, `glutin_wgl_sys`, `khronos_api` and `spirv`; lockfile presence alone does not prove that each is linked on every platform. The embedded Roboto font carries Apache-2.0 metadata. Apache's [compatibility guidance](https://www.apache.org/licenses/GPL-compatibility.html) supports GPLv3 combinations, not GPLv2-only combinations.

The sensible conservative distribution choice is a **GPLv3-compatible combined native application**, retaining MIT/permissive grants for separable components and the original NASSP per-file grants and exceptions. Choosing the permitted later GPL version for a distribution is not permission to erase original copyrights, rewrite upstream grants, or relicense unrelated assets. No such choice has been enacted by this audit.

### 4. GPL change/source/notice obligations need a release implementation

Preserve source copyright, license, linking-exception and warranty notices. Supply the applicable complete GPL text, including GPLv3 for GPLv3 code. Ensure modified GPL files carry prominent change/date notices. For example the adapted `src_lm/LEM.cpp:1-23` retains the old header; the release must review whether every modified covered file has the required modification notice. Patch manifests and Git history are useful evidence but do not by themselves demonstrate per-file compliance.

For each downloadable binary, provide exact corresponding source and build/install scripts at the same release location, with source revision, dependency revisions, Cargo lock/checksums, local dependency patches, generated-resource inputs and a reproducible build recipe. Do not rely solely on an upstream link whose branch can change. A source archive may omit genuinely separate runtime data, but cannot omit the preferred source/input for GPL-covered resources compiled into the delivered executable. Consult the actual [GPLv2 text supplied by NASSP](https://raw.githubusercontent.com/rcflyinghokie/NASSP/e731c28c0ebc1a4fe3b63f99e2006a1a8a2b42a9/NASSP-LICENSE.txt), §§1-3, and [FSF GPLv3 text in GCC's official mirror](https://raw.githubusercontent.com/gcc-mirror/gcc/master/COPYING3), §§1,4-6. A download release should implement the source-access option deliberately; a casual written-offer placeholder is insufficient.

### 5. Stock Windows XRSound/irrKlang is not the native audio implementation

`orbiter/CMakeLists.txt:12-14` returns into the native portability build. `cmake/PortableChecks.cmake:93` includes `NativeAudio.cmake`, which compiles `NativeSound.cpp` and the miniaudio adapter. The native CMake path does not invoke the stock XRSound target or irrKlang download. CMake's pinned miniaudio source is permissively licensed. The XRSound-shaped native API is not evidence that irrKlang is linked.

The stock Windows path is different. When XRSound is enabled, `Sound/XRSound/CMakeLists.txt:1-28` fetches an archived irrKlang 1.6 SDK unless `IRRKLANG_DIR` is supplied. Lines 58-60 copy `irrKlang.dll`, `ikpMP3.dll` and `ikpFlac.dll`; lines 76-78 install them. [Exact upstream build logic](https://raw.githubusercontent.com/orbitersim/orbiter/bd1d101f348da66e8c5b986633127c05e18d42c8/Sound/XRSound/CMakeLists.txt) confirms this behavior. No tracked irrKlang SDK/runtime was found in the audited source tree; a future stock-Windows artifact would nonetheless select these files through that rule.

The [vendor's license](https://www.ambiera.com/irrklang/license.html) permits specified unmodified runtime libraries in non-commercial products and otherwise restricts archive redistribution. It does not clearly grant redistribution of the two plugin DLLs merely because upstream CMake copies them. The [download page](https://www.ambiera.com/irrklang/downloads.html) now limits downloads to existing licensees. Archived availability does not establish acquisition or redistribution authority. Keep the SDK and plugin DLLs out of public source/source archives; resolve authorized build inputs and all selected runtime/plugin grants before a stock-Windows download. Disable/replace the component where practical, or require lawful separate installation without suggesting that separation excuses obligations on any binary actually shipped. Do not reuse the stock Windows target as a Linux packaging recipe.

## What the NASSP warning actually says

At **this project's legacy tree**, `NASSP/COPYING.txt:1-31` warns about combining NASSP with a non-Free, closed-source Orbiter and then refers the reader to GPLv2. The exact pinned **release434** Git tree has `NASSP-LICENSE.txt` but **no `COPYING.txt`**. The adapted `orbiter/Addons/NASSP` likewise does not contain it. This was checked with `git ls-tree`/`git cat-file` against the exact release commit, not inferred from a moving public branch.

The legacy warning states a historical legal rationale, rather than a separate enumerated license grant or additional condition; that is the audit's interpretation. It should be preserved/contextualized where the legacy material remains. The current [pinned OpenOrbiter license](https://github.com/orbitersim/orbiter/blob/bd1d101f348da66e8c5b986633127c05e18d42c8/LICENSE) is MIT, so the warning's premise does not describe that source engine. The NASSP [Project Apollo license](https://raw.githubusercontent.com/rcflyinghokie/NASSP/e731c28c0ebc1a4fe3b63f99e2006a1a8a2b42a9/Orbitersdk/samples/ProjectApollo/Doc/Project%20Apollo%20License.txt) additionally contains a linking exception for the Orbiter SDK and associated libraries while retaining GPL duties elsewhere. yaAGC has its own narrower exception. Neither the MIT change nor an exception grants rights to third-party assets, SDK archives, fonts or another author's code. Do not describe this as blanket permission for any combined Orbiter package, particularly older proprietary Orbiter binaries.

The legacy `Doc/CDK Copyright.txt:6-12` also has attribution/source and for-profit-approval conditions. The actual pinned `src_aux/{CDK,OrbiterMath}.{cpp,h}` instead carry explicit GPLv2-or-later grants, including Chris Knestrick's copyright in the CPP files. [Pinned CDK source](https://raw.githubusercontent.com/rcflyinghokie/NASSP/e731c28c0ebc1a4fe3b63f99e2006a1a8a2b42a9/Orbitersdk/samples/ProjectApollo/src_aux/CDK.cpp) corroborates this. Apply the file-specific grant to those copies, preserve the old notice as historical provenance, and verify any other CDK-derived file individually; do not announce that every CDK artifact has been relicensed or that the old condition covers no other material.

## Asset provenance and distribution boundaries

`tracked-asset-provenance.csv` compares 2,852 media/data/prebuilt files under the modern `orbiter/` tree with the actual pinned upstream trees. All 1,076 selected NASSP entries match release434 exactly or differ only by CRLF normalization (960 exact, 116 CRLF-only). Of 1,776 OpenOrbiter entries, 1,765 match exactly, two are CRLF-only, and nine are local additions: eight native fonts and one test scenario. These are provenance results, not rights clearances.

| Set | Evidence and conservative disposition |
| --- | --- |
| NASSP meshes/artwork | 310 tracked mesh-tree entries in each legacy/modern copy; modern files match the pin after permitted text normalization. Project GPL is evidence of the project's asserted grant, not proof that every incorporated artwork contributor or external image is covered. Keep author/source/permission records for the shipped subset. |
| Skylab1973 assets | `Meshes/ProjectApollo/Skylab1973/Copying and GPL.txt:1-16` grants GPLv3-or-later but refers to a manual page defining scope. That referenced `Skylab Operations Manual.PDF` was not found in the audited tree. Scope and preferred editable source need confirmation before bundling the subset. |
| NASSP textures and planetary archives | NASSP `Textures/` and `XRSound/` are not tracked in this snapshot. Actual mission staging uses external pinned data and external Moon/planet archives. Exclude these from a download until their asset-level terms are recorded, or have users lawfully acquire the exact compatible package. This does not clear the meshes, panels, sounds or other media that **are** tracked. |
| Orbiter default meshes/textures/catalogs | 34 mesh entries and 261 texture-tree entries are tracked; texture-tree bytes total about 237 MB. Upstream identity does not establish all source-image rights. Preserve dataset credits and review image/catalog source terms for anything shipped. |
| NASSP sounds | Each copy has 301 tracked sound-tree entries. Historical mission recordings, contributor recordings, sound effects and any music need an origin/rights ledger. Do not label all WAV files public domain because the subject is Apollo. |
| XRSound default audio | Source/ReadMe say MIT, but `assets/XRSound/ReadMe.txt:52` identifies third-party licensed music, Solar Serenity. The scope of that grant was not established. Exclude that track and other unclear audio until rights are documented. |
| AGC emulator versus ROMs | yaAGC emulator code is GPLv2-or-later with the preserved exception. Twenty `.bin` ROM files exist in each NASSP Config copy and have no per-file license text. The [Virtual AGC maintainer](https://www.ibiblio.org/apollo/index.html#Licensing) describes original Apollo software as public domain to the best of his non-lawyer understanding and newer emulator software as GPL. Match each ROM to its exact assembler/source revision and determine whether it is original or a later modified program; do not transfer that characterization automatically to `Artemis072NBY71`, `FP6/FP8`, `LUM69R2`, `Manche*R*`, or other variants. Publish verified source/checksums or retain ROMs as separate lawful inputs until that mapping is complete. |
| Scenarios/checklists/manuals | NASSP-authored scenarios and scripts are project content; original NASA procedures may have different provenance from modern authored PDFs, Office files and third-party scientific papers. The current tree has no tracked NASSP `Scenarios/` entries despite the runtime using external originals. Treat saved evidence and helper-generated scenarios separately from upstream mission assets. |
| Panel bitmap resources | Hundreds of BMP resources live under the source directories and are compiled/extracted into the native runtime. Excluding mission textures from a package does not exclude these resources. Record their grant and include corresponding editable/resource input where covered source requires it. |

[NASA's current media guidance](https://www.nasa.gov/nasa-brand-center/images-and-media/) distinguishes generally usable government media from third-party material and imposes attribution, endorsement and personality/branding considerations. A photo's NASA host or an Apollo filename is not a per-asset license. Avoid an endorsement claim and retain applicable creator/mission credits.

Native font TTF name tables were inspected independently. The four Roboto files explicitly identify Apache-2.0; the four JetBrains Mono files identify OFL-1.1 and their copyright. `native-font-provenance.json` records hashes and name-table evidence. Ship Apache text/notices and OFL copyright/text with embedded fonts; keep fonts under their font licenses and respect reserved-name rules. See [Roboto's license](https://raw.githubusercontent.com/googlefonts/roboto/main/LICENSE) and [JetBrains' OFL](https://raw.githubusercontent.com/JetBrains/JetBrainsMono/master/OFL.txt). These fonts are distinct from Architext and the stock Windows font bundle.

## Dependencies and source inventory

The component inventory covers engine/NASSP/D3D9/yaAGC/CDK, native SDL3/ImGui/stb/miniaudio/Lua/Corrosion, Cargo packages, fonts, Windows helpers, data and media. Native fetch revisions were checked against local dependency Git HEADs. The Cargo lock has 127 packages: 126 external packages had cached license metadata; the local `orbiter-wgpu` crate has no explicit Cargo license field. The inventory is all **locked** packages, not a claim that all are linked on every platform. Include the compiled target's resolved graph, transitive licenses/notices and checksums in each artifact's SBOM.

Keep full third-party permission/copyright/warranty texts. Choose a compatible alternative where a dependency offers alternatives; the miniaudio MIT No Attribution alternative, stb MIT alternative, and appropriate MIT alternatives for Cargo dependencies are straightforward. Apache-only packages retain Apache notices/patent terms. `unicode-ident` additionally requires Unicode-3.0 notices. Font licensing stays separate. Preserve source for GPL-covered modules and include exact dependency source/patches needed to recreate them. General development tools and normal OS system libraries are a different category from libraries copied into a downloadable bundle. Never classify every dependency as a system library without checking the shipped bytes.

D3D9 files are not uniformly MIT: examples include GPLv3-or-LGPLv3 headers in `OVP/D3D9Client/D3D9Client.cpp:4`, LGPLv2 headers in `D3D9Pad.cpp:3`, and MIT files such as `AABBUtil.cpp`. Preserve per-file notices and select a compliant GPL/LGPL route for any D3D9 binary. The optional NRLMSISE C files credit a separate author and refer to missing `DOCUMENTATION`; their included-source license context requires checking for a stock full build. Neither D3D9 nor NRLMSISE is proof that the native currently tested renderer includes those optional components.

## Existing packaging is useful prior work, not a v9 release

The sibling `nassp-ci-packaging` checkout at `bafd021` has a macOS-arm64 packaging prototype. `packaging/package_macos.py` copies native binaries/resources/config, relocates libraries, signs ad hoc, adds component notices and a corresponding-source archive with pinned fetched sources and `cargo vendor --locked`. It deliberately excludes planetary archives and NASSP mission assets. Its source archive rejects selected legacy binary suffixes. These are useful mechanisms, subject to an actual archive inspection and matching build validation.

Its profile and metadata still say **baseline**, and its launch/source/data checks target the older baseline, not v9 release434. It requires a hosted-safe test receipt, which is narrower than the current complete 104-test registration. Do not copy its success claim into a v9 release. Its executable NASSP resources still need media/source obligations reviewed even though external data are excluded. An exclude-by-suffix source filter does not resolve copyright terms for remaining files or guarantee complete corresponding source. It provides no proven Windows/Linux artifact.

## Git history, privacy and push scope

The immutable baseline has 23 reachable commits, 8,262 tracked paths, 6,825 unique reachable blobs and 1,504,624,035 uncompressed unique blob bytes. Logical checked-out file bytes total 2,008,960,158 because duplicated paths can reference the same blobs. The observed object store uses about 571 MiB of packs; that store may include objects outside the selected branch. Largest reachable blob: 43,966,440 bytes (`NASSP/Meshes/ProjectApollo/CM-VC.msh`). No reachable blob exceeds 50 or 100 MiB. GitHub's [large-file guidance](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) therefore does not identify a file-size rejection, but this is a large imported tree, and host transfer/quota behavior was not tested.

The metadata-only scanner inspected 4,501 text blobs with high-signal private-key, GitHub/Slack token, AWS key, authenticated URL and literal credential-assignment patterns. **No candidates matched.** It skipped binary blobs and 25 blobs larger than 8 MiB. Office/PDF embedded metadata, compressed archives and binary strings were not exhaustively scanned; this is not a secrets guarantee. It reports no secret values. Review the final diff, release inputs and intended refs again before publishing.

Forty-eight blob versions contain local workspace paths and/or task/Library identifiers. These are reproducibility/privacy metadata, not demonstrated credentials. Confirm whether machine/account paths, conversation identifiers and standard author/email metadata may be public; normalize unnecessary workstation paths in user instructions while keeping useful hash evidence. Raw VM disks, software installers, application captures and private evidence directories are not in the baseline tree and must not be swept into a release archive. Use an explicit publication allowlist, not a recursive workspace upload.

The checkout's immediate `origin` is a local repository, `nassp-macos-protocol`; a chain of older local origins points toward a now-unavailable temporary checkout. A hosted target and its current visibility were not verified here. Therefore this audit neither authorizes nor performs a push or visibility change. A private source backup, public Git publication and public binary release are three different actions. Rights restrictions can also matter on private redistribution, so do not promise that private hosting itself clears a restrictive asset. Publish only the chosen audited refs; avoid mirror-pushing unrelated refs/reflogs.

## User decisions needed

1. Choose the public boundary: resolve the full imported tree's rights, or create an audited source/patch publication with excluded assets/binaries removed from its reachable history. Preserve the current local/demo history independently.
2. Choose licensing for **original** work: recommended MIT for independent engine/platform glue and helpers intended for upstream adoption; preserve existing GPL NASSP derivative grants and use a GPLv3-compatible combined preview. An all-GPLv3 original contribution policy is also possible. Neither choice changes third-party grants. Decide the local Rust crate's explicit license and contributor/owner notice.
3. Choose whether initial downloads include audited mission media or require separately acquired matching NASSP/planetary data. Record permissions for panel resources, AGC variants and any included audio before shipping them.
4. Choose the first supported artifact: macOS arm64 bounded preview is evidenced; Intel macOS, native Windows-port and Linux downloads require their own clean builds and platform tests. Keep the stock Windows reference separately labeled.
5. Confirm public repository destination/visibility, commercial-distribution intent, unnecessary personal metadata treatment, and whether external rights confirmation or specialist legal review should be commissioned. No external maintainer or copyright holder was contacted.

The accompanying compliance plan gives concrete release gates; it does not mark those gates completed.
